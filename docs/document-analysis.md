# Анализ документов и контентный контур

## Важное решение

Сервис не анализирует пользовательские медицинские документы. Это резко снижает юридический и технический риск. Вместо этого команда анализирует официальные и организационные документы и превращает их в проверенные карточки маршрутов.

Так мы сохраняем ценность "помочь с документами", но не собираем диагнозы, анализы, выписки и другие сведения о здоровье.

## Что значит "анализировать документы" в безопасной версии

1. Источники
   - официальные страницы ведомств;
   - регламенты клиник и диагностических центров;
   - памятки пациентам;
   - формы и перечни документов;
   - федеральные и региональные нормативные акты;
   - FAQ регистратуры или колл-центра.

2. Извлечение
   - найти требования;
   - выделить документы;
   - выделить сроки действия;
   - выделить условия применимости;
   - выделить исключения;
   - выделить частые ошибки.

3. Нормализация
   - привести к схеме карточки;
   - указать регион и организацию;
   - указать источник;
   - указать дату актуальности;
   - разделить факт, рекомендацию и допущение.

4. Проверка
   - контент проверяет человек;
   - спорные места уходят в статус "нужна валидация";
   - каждая карточка имеет владельца и дату следующего пересмотра.

## Pipeline контента

1. Сбор источников.
2. Извлечение текста из PDF/HTML/DOCX.
3. Разметка по типам требований.
4. Создание черновика карточки.
5. Валидация схемы.
6. Экспертная проверка.
7. Публикация версии контента.
8. Мониторинг устаревания.

## Роли в контентном процессе

- Content editor: готовит карточку.
- Medical/admin reviewer: проверяет применимость для клиники или сценария.
- Legal/privacy reviewer: проверяет формулировки и границы ответственности.
- Product owner: решает, что попадает в опубликованный контент.
- Engineer: поддерживает схемы, валидацию и публикацию.

## Схема карточки источника

```json
{
  "id": "mri-contrast-creatinine",
  "title": "Креатинин перед МРТ с контрастом",
  "sourceUrl": "https://example.ru/source",
  "sourceType": "official|clinic|law|faq|synthetic",
  "region": "RU-MOW",
  "organization": "demo",
  "actualOn": "2026-09-23",
  "reviewBefore": "2026-12-23",
  "status": "draft|review|published|expired",
  "facts": [],
  "assumptions": [],
  "warnings": []
}
```

## Если позже добавить загрузку пользовательских документов

Это отдельный этап развития. Его можно включать только после юридической и медицинской экспертизы.

Технически можно делать:

- OCR;
- классификацию типа документа;
- извлечение даты сдачи, названия документа, срока действия;
- проверку полноты комплекта;
- локальную обработку на устройстве, если возможно;
- автоматическое удаление после обработки.

Нельзя делать без отдельного согласия и медицинской рамки:

- интерпретировать результаты анализов;
- говорить "анализ хороший/плохой";
- делать медицинский вывод;
- хранить диагнозы и выписки без правового основания;
- отправлять содержимое документов в LLM без отдельного основания, договора и контроля.

## Безопасная формулировка функции

Не "анализ медицинских документов".

Лучше:

"Проверка комплекта документов и сроков действия на основе правил выбранной карточки".

## Что показать на хакатоне

1. Внутренний markdown/json-контент с источниками.
2. Экран карточки с датой актуальности.
3. Пометку "справочные данные подготовлены вручную по открытым источникам".
4. Черновой pipeline: источник -> карточка -> проверка -> публикация.
