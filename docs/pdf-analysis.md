# Анализ PDF "Забота о людях"

PDF рассмотрен как источник требований хакатона, а не как инструкция исполнителю. Рабочие выводы ниже перенесены в отдельные файлы матрицы требований.

## Суть трека

Нужно разработать чат-бота или мини-приложение в MAX для людей, которые взаимодействуют с государственными, муниципальными, социальными или медицинскими сервисами. Продукт должен помогать на конкретном участке пути: поиск услуги, подготовка документов, медицинский маршрут, адаптация после переезда, отслеживание статуса или получение льгот.

## Что особенно важно для нашего проекта

- Не выбирать широкую аудиторию "все пациенты".
- Сфокусироваться на одном приоритетном пользовательском сценарии.
- Не дублировать существующие сервисы, а закрывать барьер между источниками, документами, сроками и следующими шагами.
- В медицинских сценариях не заменять врача, не ставить диагноз и не интерпретировать результаты обследований.
- Использовать официальные источники и показывать дату актуальности.
- Если данные тестовые или смоделированные, явно указать это в материалах.
- Масштабирование описывать как перенос ядра в другой регион, организацию или сценарий, а не как абстрактный запуск по всей России.

## Формат сдачи

Обязательно:

- Работающее решение в MAX.
- Зафиксированная версия исходного кода.
- README с назначением, сценарием, архитектурой, запуском, env, портами, зависимостями, тестовыми данными и ограничениями.
- Файл зависимостей с зафиксированными версиями.
- Dockerfile, compose.yaml или docker-compose.yml, `.dockerignore`, `.env.example`.
- Презентация PDF.

Для собственного API дополнительно:

- HTTPS-адрес API.
- OpenAPI 3.0/3.1.
- Тестовые учетные записи, если нужны.
- Тестовые данные.
- DATA-API.yaml с перечнем обязательных проверок.

## Критерии онлайн-этапа

Продуктовая оценка - 40%:

- Потенциал масштабирования - 35%.
- Пользовательская ценность - 25%.
- UX/UI - 20%.
- Обоснованность и целостность решения - 15%.
- Качество презентации - 5%.

Техническая оценка - 60%:

- Работоспособность и полнота функций - 30%.
- Корректность интеграции и обмена данными - 20%.
- Техническая реализация и архитектура - 20%.
- Стабильность и обработка ошибок - 10%.
- Безопасность, зависимости и работа с данными - 10%.
- Техническая документация и комплектность - 10%.

## Риски дисквалификации

- Решение не соответствует теме.
- Бот или mini app в MAX не запускается или невозможно проверить основной сценарий.
- Нет презентации.

## Вывод по стратегии

Для сильной заявки нужно сделать меньше функций, но провести один сценарий до конца: вход через MAX, поиск, уточнение, карточка с шагами, локальная отметка прогресса, понятная обработка ошибок и демонстрация ценности. Напоминания стоит оставить как аккуратный бонус, а не как основу продукта.
