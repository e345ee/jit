# Проверка соответствия треку

## Короткий вывод

Тема подходит к треку "Забота о людях", если позиционировать продукт как навигатор пациента по медицинским и связанным государственным маршрутам: документы, сроки, учреждения, типовые ошибки, следующий шаг. Это ровно попадает в область "цифрового помощника пациента" и взаимодействия с медицинскими, социальными и государственными сервисами.

Продукт станет рискованным для трека, если описывать его как медицинского AI-ассистента, анализатор результатов обследований или сервис, который принимает решение вместо врача, МСЭ, ФНС, МФЦ или другой организации.

## Формулировка для заявки

Пациент перед обследованием, госпитализацией или оформлением связанной услуги хочет быстро понять, какие документы нужны, где их получить, сколько они действуют и какой шаг следующий, но требования разбросаны между врачом, регистратурой, лабораторией, клиникой, МФЦ, Госуслугами и ведомственными сайтами. Из-за этого возникают переносы записи, повторные обращения и тревога. "Навигатор для пациента" собирает маршрут в одну понятную карточку, адаптирует его через 1-2 вопроса и помогает не забыть шаги локальным чек-листом.

## Соответствие требованиям хакатона

| Требование | Статус | Что нужно сделать |
| --- | --- | --- |
| Тематика "Забота о людях" | Подходит | Держать фокус на гос/соц/медицинском маршруте, а не на общем wellness. |
| Конкретная аудитория | Частично | Сузить до пациентов перед диагностикой/госпитализацией в первом MVP. |
| Конкретная проблема | Подходит | Показать ошибки из-за сроков документов и разрозненных источников. |
| MAX как среда | Подходит | Бот как вход, mini app как основной интерфейс. |
| Проверяемый основной сценарий | Нужно реализовать | Сценарий "МРТ с контрастом" пройти от поиска до чек-листа. |
| Не заменять специалиста | Подходит при ограничениях | Писать маршруты, сроки, источники; не интерпретировать симптомы и анализы. |
| Официальные источники | Нужно усилить | Для каждой карточки хранить источник, регион, дату актуальности. |
| Тестовые данные обозначены | Нужно реализовать | В README и карточках явно пометить модельные данные MVP. |
| Docker и воспроизводимость | Нужно реализовать | Добавить Dockerfile, compose.yaml, lock-файлы. |
| Безопасность и секреты | Подходит | Токены только в `.env`, репозиторий без секретов. |
| Масштабирование | Подходит | Масштабировать через контентные пакеты по регионам/сценариям. |

## Главный риск

Самая тонкая зона - обработка документов и медицинских данных. Для хакатона лучше не загружать пользовательские меддокументы в MVP. Документный анализ можно показать как внутренний контентный pipeline: команда анализирует официальные источники и превращает их в проверенные карточки. Пользователь вводит только безличные параметры вроде "есть направление", "регион", "тип оплаты".

## Что усилить для победной заявки

1. Сделать один сценарий демонстрационно безупречным.
2. Добавить экран "источник и дата актуальности".
3. Показать, что чек-лист локальный и не является медицинской картой.
4. Добавить опциональное напоминание как платформенный плюс MAX.
5. Подготовить понятный план пилота с диагностическим центром или поликлиникой.

## Вывод по прошлогодним победителям

По приложенным слайдам видно, что успешные проекты формулировались коротко и практически: "чат-бот для анализа состава продуктов", "календарь быстрого бронирования", "мини-приложение для цифрового контроля знаний". Для нас нужна такая же простая формула:

"Мини-приложение в MAX, которое превращает сложный медицинский маршрут в понятную карточку шагов, сроков и документов".
