# Подготовка продукта к продаже

## Кому продавать

### B2B: медицинские организации и диагностические центры

Ценность:

- меньше звонков в регистратуру по типовым вопросам;
- меньше переносов записи из-за забытых документов или просроченных анализов;
- единый стандарт объяснения маршрута пациенту;
- быстрый запуск без глубокой интеграции с МИС.

Покупатель:

- частная клиника;
- диагностический центр;
- сеть клиник;
- страховая компания ДМС;
- медицинский агрегатор;
- региональный оператор медицинских сервисов.

### B2G/B2B2G: региональные ведомства, МФЦ, подведомственные организации

Ценность:

- понятные жизненные ситуации;
- снижение повторных обращений;
- поддержка инициативы "Государство для людей";
- возможность быстро адаптировать контент под регион.

### B2C как вторичный канал

Прямой потребительский запуск возможен, но сложнее монетизируется. Для хакатона лучше показывать B2B/B2G-модель: пользователь получает бесплатный доступ, платит организация за внедрение, контент, поддержку и аналитику.

## Что именно продаем

1. Базовая платформа
   - MAX bot + mini app.
   - Каталог ситуаций.
   - Локальный чек-лист.
   - База знаний.
   - Напоминания.

2. Контентный пакет
   - Набор карточек под конкретную организацию или регион.
   - Источники, дата актуальности, владелец контента.
   - Регулярное обновление.

3. Внедрение
   - Настройка бота.
   - Подключение mini app.
   - Брендинг.
   - Пилотный запуск.
   - Обучение администратора.

4. Поддержка
   - SLA.
   - Обновления контента.
   - Мониторинг ошибок.
   - Отчеты по метрикам без медицинских данных.

## Упаковка для первого пилота

Минимальный коммерческий пилот:

- 5-10 карточек ситуаций;
- 1 организация или 1 регион;
- запуск в MAX;
- QR/deeplink из регистратуры, сайта клиники или памятки пациента;
- базовая аналитика: открытия, завершения, клики по шагам, частые поисковые запросы;
- отчет через 2-4 недели.

## Модель монетизации

1. Setup fee
   - Разовая настройка: бот, mini app, первый контентный пакет.

2. Subscription
   - Ежемесячная поддержка, хостинг, обновления, мониторинг.

3. Content maintenance
   - Отдельная цена за актуализацию карточек, если правила часто меняются.

4. Enterprise package
   - Интеграции, брендирование, расширенная аналитика, несколько филиалов.

## Коммерческое позиционирование

Не "медицинский ИИ". Не "замена Госуслуг". Не "автоматическое оформление".

Правильная рамка:

"Навигатор маршрутов пациента: снижает число ошибок перед визитом и помогает учреждению объяснять сложные требования простым языком".

## Необходимые соглашения и документы

### Для пользователя

1. Пользовательское соглашение
   - Что делает сервис.
   - Что сервис не делает.
   - Ограничение ответственности.
   - Запрет использовать сервис как медицинское заключение.

2. Политика конфиденциальности
   - Какие данные собираются.
   - Зачем они нужны.
   - Где хранятся.
   - Как удалить данные.

3. Согласие на обработку персональных данных
   - Нужно, если есть идентификатор пользователя, chat id, напоминания, обратная связь или аналитика, связанная с пользователем.

4. Отдельное согласие на обработку специальных категорий данных
   - Нужно только если продукт начнет принимать или хранить сведения о здоровье, диагнозы, результаты анализов, медицинские документы.
   - Для текущего контура лучше не входить в эту зону.

5. Согласие на уведомления
   - Для напоминаний через бота.
   - Текст напоминания должен быть нейтральным: "истекает срок документа", без диагноза и деталей заболевания.

6. Медицинский дисклеймер
   - Сервис носит информационный и навигационный характер.
   - Окончательные требования уточняются у медицинской организации или специалиста.

### Для B2B/B2G-клиента

1. Договор пилота
   - Цель, срок, метрики, контур пользователей, ответственность сторон.

2. Договор оказания услуг или лицензия
   - Право использования mini app и бота.
   - Поддержка, обновления, ограничения.

3. DPA / поручение на обработку персональных данных
   - Если команда продукта обрабатывает данные по поручению клиники или организации.

4. SLA
   - Доступность, время реакции, порядок инцидентов.

5. Контентное соглашение или RACI
   - Кто утверждает карточки.
   - Кто отвечает за медицинскую/юридическую корректность.
   - Как часто обновляется контент.

6. NDA
   - Если клиника передает внутренние регламенты, скрипты регистратуры или непубличные документы.

## Пакет для первой продажи

- Демо в MAX.
- Презентация на 10-12 слайдов.
- One-pager для руководителя клиники.
- Таблица экономического эффекта.
- Карта пилота на 2-4 недели.
- Список документов и согласий.
- Пример карточки с источниками.
- Политика обработки данных в короткой форме.

## Метрики для клиента

- Количество открытий маршрута.
- Доля пользователей, дошедших до чек-листа.
- Топ поисковых запросов.
- Частые ошибки, которые пользователи открывают.
- Снижение повторных звонков по выбранному сценарию.
- Снижение переносов записи из-за документов.
- NPS/оценка понятности после карточки.

## Roadmap после хакатона

1. Hackathon release: справочник, чек-лист, напоминания, расширенный набор карточек.
2. Pilot: контент под конкретную клинику, QR/deeplink, базовая аналитика.
3. Product: кабинет контент-редактора, workflow согласования, версии карточек.
4. Scale: региональные пакеты, интеграции с CRM/колл-центром/МИС, мультиязычность.
