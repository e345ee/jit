# 09. Стабильность и ошибки

## Требование

Решение должно стабильно работать при повторном прохождении сценария. Ошибки и некорректные действия пользователя должны обрабатываться предусмотренным образом. После ошибки пользователь должен продолжить работу без полного перезапуска.

## Применение к проекту

Сценарии ошибок:

- Нет сети.
- API недоступен.
- Карточка не найдена.
- Пустой поиск.
- Не удалось создать напоминание.
- Контент устарел или не загрузился.

## Механики устойчивости

- Кэш последней версии справочника.
- Retry для сетевых запросов.
- Healthcheck API и worker.
- Очередь уведомлений.
- Идемпотентные операции напоминаний.

## Проверка

- Пройти сценарий 5 раз подряд.
- Отключить API и убедиться, что интерфейс показывает fallback или понятную ошибку.
- Создать, отменить и повторно создать напоминание.
