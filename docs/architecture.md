# Архитектура

## Цель архитектуры

Сделать MVP, который можно быстро проверить в MAX, воспроизвести через Docker и затем масштабировать по регионам, сценариям и типам учреждений без переписывания ядра.

## Основные компоненты

1. MAX bot
   - Точка входа для пользователя.
   - Отправляет приветствие, короткое меню и ссылку на мини-приложение.
   - При необходимости принимает команды для напоминаний.

2. MAX mini app
   - Основной интерфейс справочника.
   - Поиск, категории, карточки ситуаций, карточки знаний, локальный чек-лист.
   - Хранит отметки чек-листа на устройстве через localStorage или DeviceStorage.

3. Content API
   - Отдает карточки ситуаций, дерево решений, карточки базы знаний, версии контента и источники.
   - Не хранит медицинские данные пользователя.
   - Может работать с подготовленными JSON/Markdown-данными на MVP.

4. Admin/content pipeline
   - Контент описывается в структурированном формате: `content/situations/*.json`, `content/knowledge/*.md`.
   - Перед сборкой проходит валидацию: обязательные поля, сроки, источники, дата актуальности, регион.

5. Reminder service, optional
   - Включается только по явному действию пользователя.
   - Хранит минимальные данные: chat id, тип напоминания, дату события, текст без диагноза и медицинских подробностей.
   - Отправляет уведомление через бота.

6. Observability
   - Логи без персональных и медицинских данных.
   - Метрики: прохождение основного сценария, ошибки загрузки, время ответа API, клики по шагам.

## Поток основного сценария

1. Пользователь открывает бота в MAX.
2. Бот предлагает открыть мини-приложение.
3. Пользователь выбирает категорию или вводит запрос.
4. Мини-приложение показывает подходящие ситуации.
5. Пользователь открывает карточку.
6. При необходимости приложение задает 1-2 уточняющих вопроса.
7. Пользователь получает адаптированный список шагов.
8. Пользователь отмечает выполненные пункты локального чек-листа.
9. При желании пользователь включает напоминание о сроке документа.

## Данные и состояние

- Контент справочника: серверная часть, версионируемые файлы.
- Прогресс чек-листа: только устройство пользователя.
- Напоминания: серверная часть, только минимальные технические данные.
- Медицинские документы, диагнозы, результаты анализов: не храним.

## Устойчивость

- Mini app кэширует последнюю версию справочника на устройстве.
- Content API отдает статический fallback-контент при проблемах с базой.
- Reminder service работает через очередь задач, чтобы сбой отправки не ломал основной сценарий.
- API проектируется идемпотентно: повторный запрос не создает дубликаты напоминаний.
- Healthcheck endpoints для Docker и будущего деплоя.
- Явные empty/error states в интерфейсе: нет результатов, нет сети, устаревшие данные, ошибка напоминания.

## Распределенность

MVP можно запустить монолитно в одном Docker Compose, но границы компонентов сразу выделены:

- `web`: React mini app.
- `bot`: обработчики MAX Bot API.
- `api`: контент, поиск, решения, напоминания.
- `worker`: отложенные уведомления.
- `postgres`: напоминания и служебные события.
- `redis`: очередь задач и rate limiting.

Такой подход дает простой MVP и понятный путь к масштабированию: web можно вынести на CDN, API масштабировать горизонтально, worker запускать отдельно, контент обновлять через pipeline.

## Границы ответственности

Продукт не ставит диагноз, не интерпретирует симптомы и результаты обследований, не заменяет врача, МФЦ или ведомство. Он объясняет порядок действий, сроки, типовые ошибки и источники, а также помогает не забыть шаги.
